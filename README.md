# Alex Morgan Portfolio

A responsive, typography-led personal portfolio built with React and Express. The frontend presents selected work, background, skills, and a contact form. The backend validates and stores messages in Supabase PostgreSQL.

## Architecture & workflow

- `client/` is a Vite-powered React single-page application. It owns navigation, responsive presentation, resume PDF generation, and contact-form loading/success/error states.
- `server/` is an Express API. `POST /api/contact` validates input, applies rate limiting, and inserts a record through the Supabase JavaScript client.
- The browser sends the form payload to the Express API. Express uses server environment variables to reach Supabase, then returns a standard JSON response to the UI.

## Supabase setup

In the Supabase SQL Editor, run:

```sql

create table if not exists public.contacts (
	id bigint generated by default as identity primary key,
	name text not null,
	email text not null,
	message text not null,
	created_at timestamptz not null default now()
);

alter table public.contacts enable row level security;

drop policy if exists "Allow anonymous contact inserts" on public.contacts;

create policy "Allow anonymous contact inserts"
on public.contacts for insert
to anon
with check (true);
```

The form submits to the Express API, which inserts into `public.contacts` using the Supabase anon key. The server returns a configuration error until the environment variables below are filled in.

The server only performs inserts. Keep Supabase credentials in the server environment, and never commit `.env`.

## Environment variables

Copy `server/.env.example` to `server/.env` and add your Supabase project values. In PowerShell:

```powershell
Copy-Item server/.env.example server/.env
```

Open `server/.env` and replace the placeholder Supabase URL and anon key. Optional client override:

```bash
VITE_API_URL=http://localhost:5001
```

## Local startup

```bash
npm install
npm install --prefix client
npm install --prefix server
npm run dev
```

The client runs at `http://localhost:5173` and the API at `http://localhost:5001`. Vite automatically selects the next available client port if 5173 is busy.

To run them separately in PowerShell:

```powershell
npm run dev --prefix client
npm run dev --prefix server
```

To stop all Node development processes before restarting:

```powershell
taskkill /F /IM node.exe
taskkill /F /IM npm.exe
```

To verify the API:

```powershell
Invoke-RestMethod http://localhost:5001/api/health
```

## Render deployment

This repository includes `render.yaml` for a single Render web service. The service builds the Vite client, serves it from Express, and exposes the API at `/api`.

1. Push the repository to GitHub or GitLab.
2. In Render, choose **New > Blueprint** and select the repository.
3. Confirm the `render.yaml` configuration and create the service.
4. In the service's **Environment** settings, set:
	- `SUPABASE_URL`: your Supabase project URL.
	- `SUPABASE_ANON_KEY`: your Supabase anon/public key.
	- `CLIENT_URL`: the deployed Render URL, for example `https://portfolio-xxxx.onrender.com`.
5. Deploy or trigger a new deploy. Render uses its own `PORT`; do not set a fixed production port.
6. Verify `https://your-render-url.onrender.com/api/health` returns `{ "ok": true }` and open the root URL to test the portfolio and contact form.

`VITE_API_URL` is intentionally not required in Render. The production client calls the API through the same origin. Keep `server/.env` for local-only secrets and never commit it.
